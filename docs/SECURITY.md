# Security boundaries and release gates

The trusted entry is a live Managed Better Auth session, not a client org header, session-data cache, form actor, unverified email or mutable user metadata. All Server Actions and REST mutations authenticate and recheck membership before sensitive SQL. REST requires exact Origin and bounded actual body bytes/deadlines. Next's Server Action origin protections remain enabled. Errors return short sanitized messages, not raw SQL/stacks or secrets.

Opaque provider tokens live only in authenticated-encryption HttpOnly cookies. Server-only cookie secret never reaches the browser. Invalid/tampered/expired envelopes fail closed. Every sensitive request revalidates with the provider without cookie cache; verification, expiry and user/session consistency are checked. OTP and rate/attempt limits are enforced by Managed Better Auth; local fixture requires verification and proves old sessions fail after password reset. Hosted configuration and delivery must be independently verified.

Database URL is server-only. Runtime role must be dedicated, NOINHERIT, NOBYPASSRLS, non-owner, no role/database creation. The application refuses stronger connections. It uses SET LOCAL ROLE plus transaction-local verified subject/org settings, parameterized SQL and explicit tenant predicates. Context is cleared on transaction completion; membership is locked/rechecked. Owner-only functions and append-only audit grants remain separate. Cross-tenant FKs and RLS protect mistakes and guessed IDs even if the server omits a predicate. Tests reject role escalation, ID changes, missing context, audit tampering and attempts to disable triggers/RLS.

**Trust limit:** the private DB runtime credential authorizes the server to establish verified actor context. Possession of that credential could impersonate a context; it is not a public database API key. A compromised application server/DB credential or database administrator is outside ordinary-user RLS isolation. Keep runtime and migration credentials separate, restrict network access and rotate through an approved incident process. No claim of cryptographic DB attestation or administrator-proof audit is made.

CSRF and callbacks: no open redirects; OTP replaces provider confirmation/reset links. Public auth errors are generic. Session revocation is checked live, not inferred from a locally deleted cookie. Private pages and REST are no-store. Proxy sets cache headers only; it is never the authorization boundary. CSP disallows frames and browser connections to database/auth providers; inline scripts remain necessary, development-only eval supports React tooling. Browser bundle checks must remain free of database/cookie-secret values.

Imports: 5 MB file, 1,000 rows, 50 columns, 5 sheets, bounded ZIP entries/expanded bytes/ratio/cells; encrypted/macro/formula/external/entity/huge workbooks rejected. No formula evaluation; CSV reports neutralize formula prefixes. All mapped rows validate before staging; stage+commit is one SQL transaction. Job locks/fingerprints handle retries, conflicts are explicit, failure rolls back customers/contacts/offers/audit together. Staging cleanup is privileged maintenance, never falsely described as an automatic job.

**Hosted gates still required:** correct Neon project/branch, constrained runtime URL with verify-full TLS, true OTP requirement and reset revocation settings, test-only email delivery/abuse limits, actual two-user hosted tests, provider usage/account billing limits, cleanup schedule, retention/backups/monitoring and legal review. Local PostgreSQL/Better Auth success does not prove hosted Neon or Render readiness. No paid service, automatic overage upgrade or production deployment has been enabled.
